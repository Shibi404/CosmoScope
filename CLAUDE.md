## Project

**CosmoScope** is an AR/VR mobile application (Godot 4.7, Mobile renderer) whose single purpose is to convey the true **scale and spatial layout of the Solar System** — something flat diagrams fail at. It targets a phone/tablet only; there is **no VR headset**.

Two modes solve two halves of that one problem:
- **AR mode** (ARCore/ARKit): place planets on a real surface, walk around them, tap for facts → conveys *relative size*.
- **VR mode** (Google Cardboard–style stereoscopic): phone in a holder, stand at the center of the system → conveys *scale and distance*.

## Critical constraints & decisions

- **Renderer is Mobile (Vulkan).** Do not switch to Forward+ — it will not run acceptably on target phones. Compatibility renderer is the only acceptable fallback (older devices / AR plugin issues).
- **VR is DIY, not OpenXR.** Because there is no headset, VR is built by hand: two `Camera3D` nodes rendering to a split-screen viewport, a barrel/lens-distortion shader, and head-tracking from the phone's sensors (`Input.get_gyroscope()`, `get_accelerometer()`, `get_magnetometer()`). OpenXR is irrelevant here. Interaction is gaze + dwell (or screen tap / Cardboard button).
- **AR is the highest-risk part.** Godot 4.x mobile AR depends on a community ARCore/ARKit plugin. Keep AR scope minimal: plane detection + tap-to-place only. If the plugin is uncooperative, fall back to marker-based AR (printed image → model).
- **Language is undecided (C# vs GDScript).** The project was scaffolded as a **.NET/C# project** (`project.godot` has a `[dotnet]` section, `assembly_name="CosmoScope"`), but no `.csproj`/`.sln` exists yet. GDScript is recommended (no build step, far more XR tutorials). Confirm the choice with the user before writing gameplay scripts.

## Working with Godot (no traditional build/lint/test)

There is no build/lint/test toolchain yet. Godot workflow:
- **Run in editor:** open the project in the Godot 4.7 editor and press F5 (play). CLI: `godot --path .`
- **Run headless / check for load errors:** `godot --headless --path . --quit`
- **Mobile export** requires one-time setup (Editor → Manage Export Templates, plus Android SDK/JDK paths in Editor Settings). iOS builds require a Mac. This has not been configured yet.
- If C# is kept, a `dotnet build` step will exist once a solution is generated by the editor; GDScript needs no build.
